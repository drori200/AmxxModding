## Reproduction

Run these commands from the project directory. Python 3, a C compiler, Make, and
CMake are needed. No research command installs to a system directory or changes
the production compiler. Linux x86-64 is the current host; cell width is configured
separately from the host architecture.

```sh
# Optional isolated CMake installation when CMake is unavailable:
python3 -m venv .cache/research/python
.cache/research/python/bin/pip install cmake==4.4.3

python3 -B research/tools/toolchains.py --current
python3 -B research/tools/toolchains.py --verify-only
python3 -B research/tools/test_pawn_audit.py
python3 -B research/tools/pawn_lab.py
python3 -B research/tools/pawn_examples.py
python3 -B research/tools/pawn_defects.py
python3 -B research/tools/upstream_pawn.py \
  --source .cache/research/toolchains/pawntest \
  --compiler .cache/research/build32/pawncc \
  --runner .cache/research/build32/pawnrun \
  --include .cache/research/toolchains/pawn-stable/include \
  --output research/evidence/pawn-upstream-results.json
python3 -B research/tools/pawn_gate.py --record
```

Some commands currently return failure because they reproduce defects or expose
unmet coverage. Read their JSON reports. Do not change an expected result merely
to make a command succeed. `pawn_defects.py` records observations and does not
issue a proficiency verdict. Use `pawn_lab.py --case <id>` for a focused check;
focused runs cannot replace the full-suite report.

Compiler and VM processes receive CPU, memory, output, and wall-clock limits.
Invalid-memory examples are excluded from unchecked correctness profiles. The
small C host only accepts bytecode generated by this lab; it is not an untrusted
bytecode sandbox. Its custom `check`, `identity`, and `native_error` functions
are test instruments, not PAWN language primitives.

Setup and tests use a nonblocking shared/exclusive toolchain lock. An overlapping
setup is rejected before it can replace a tool under test. After changing only the C test host,
`python3 -B research/tools/toolchains.py --hosts-only` rebuilds it without changing
the compiler or optional modules. Original archives are hash-checked before use;
every extracted file is also compared with the archive. Changed files are rejected
without overwriting them. Compilation selects the versioned empty `empty.cfg`
explicitly; ambient `pawn.cfg` settings cannot silently change the test profile.
research caches and binaries live under `.cache/research/`.

## Advancement rule

The gate checks current source, configuration, tool, and result hashes. It also
requires an evidence disposition for every inventory item, reviewed corrections,
independent exercises, and bounded treatment of defects. Unreviewed questions or
stale results keep the gate closed. A deliberate failing test can be useful
evidence, but an unexplained failure cannot count as verified semantics.

Research code lives under `research/`; production plugin discovery is configured
under `plugins/` and the pinned modding-kit directories. Research fixtures use
`.p` and `.amx`; they do not belong in the production distribution. The retained [production check](evidence/production-isolation.json) verified
50 production plugins. A final check after subsequent work and the requested
cited PDF remain outstanding.
